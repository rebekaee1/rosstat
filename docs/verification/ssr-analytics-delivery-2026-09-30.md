# Доставка аналитики годовых SSR-страниц — 30.09.2026

## Подтверждённые дефекты и локальное исправление

1. **Кэш старого entry.** Реальный Chrome получил `/assets/behavior-standalone.js` из disk cache: Last-Modified 13.08.2026, 138 bytes, `max-age=31536000, public, immutable`. Его `behavior-B84DmEeD.js` отвечает 404. Origin отдаёт другой, действующий entry: 316 bytes, Last-Modified 29.09.2026, `no-cache, must-revalidate`, импорт `rsyFloorAd-Dwi1ecj-.js`. Изменение серверного заголовка не заставляет уже свежий immutable-кэш перечитать ответ. Footer RU/EN теперь добавляет `?v=` с SHA-256 обнаруженного SPA shell; nginx по-прежнему выбирает exact location по path, без дополнительного SSR HTTP-запроса. 404 и fallback тоже меняют cache key. Четыре новых регрессионных теста сначала падали, после исправления проходят.
2. **Потеря после отправки.** Реальный `flush` до исправления очищал очередь до результата fetch и проглатывал отказ; следующий flush не повторял batch. Новая очередь доставки хранится только в ограниченной памяти, повторяет временные сбои с тем же batch_id/body, соблюдает consent и отмену поколения. Обычная доставка подтверждается HTTP success и JSON `accepted:true`; HTTP 200 с `accepted:false` завершает попытки без подтверждения портрета. Нечитаемый ответ повторяется в пределах лимита. Поздний ответ после отказа от аналитики или истечения срока не подтверждается.
3. **Ложное подтверждение Redis.** Инъекция ошибки commit в реальный API давала 500/0 строк, после чего повтор с тем же batch_id возвращал 200/duplicate/0. Новый claim имеет состояния pending/done: конкурентный незавершённый запрос возвращает 503 с Retry-After, done ставится после commit, ошибка освобождает только собственную lease. Пять новых регрессий включают failed commit, конкуренцию, чужой ownership token, отказ Redis и старый неопределённый marker.

Сама коррекция не требует миграции БД. Дедуп остаётся best effort при потере Redis, истечении lease или сбое между commit БД и сохранением done; exactly-once не заявляется. v2 marker не принимает старый pre-commit `1` за доказанную запись, поэтому переход может допустить редкий дубль старого повторного батча.

Лимиты доставки: четыре батча и 128 KiB в RAM, каждый body до 48 KiB; четыре попытки за 60 секунд с паузами 1/3/10 секунд. Network error, 429 и 5xx повторяются; более длинный `Retry-After` соблюдается, остальные 4xx завершают попытки. При переполнении или истечении срока события могут быть потеряны. Обычный fetch не использует keepalive. На уходе суммарно допускается до 48 KiB: [Fetch Standard](https://fetch.spec.whatwg.org/#http-network-or-cache-fetch) ограничивает общую keepalive-очередь 64 KiB, поэтому бюджет делится с другими сборщиками. По [Beacon specification](https://w3c.github.io/beacon/#sendbeacon-method), `sendBeacon:true` подтверждает постановку в очередь, а не запись на сервере. Обход блокировщика или отказа посетителя не реализован.

Независимый review проверил семантическое подтверждение, поздний JSON после revoke/expiry, Retry-After для 5xx, лимиты очереди, Redis ownership и сбой commit. Целевые проверки: 56 frontend tests (22 новых сценария транспорта), 67 backend API/analytics tests и 59 SSR tests проходят. Отдельный независимый прогон: 32 frontend и 5 backend tests проходят.
