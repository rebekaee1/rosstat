### Проверены дополнительные удержанные источники

- **ClickHouse:** `clickhouse-search-copy.ndjson.gz`, позднейший отдельный
  read-only снимок: 6 527 строк, 3 905 уникальных id и 2 622 повторные строки.
  Все id, имена событий и параметры совпадают с PostgreSQL snapshot;

  для времени данного аудита используется PG. Доказательство — manifest.
- **nginx:** `nginx-search-requests.ndjson.gz`, просмотрены все 15 удержанных
  `/var/log/rosstat-nginx/security.log*`, включая gzip-ротации. Найдено
  **1 108** запросов к search API за **16.09–30.09.2026**: 622 HTTP 200,
  483 HTTP 499, 2 HTTP 404, 1 HTTP 422. В 1 106 строках непустой query;
  60 разных хэшей IP и 4 запроса с явным bot/automation UA. Это не число
  людей или попыток поиска. Сырой IP хэшируется на сервере до передачи.
  Логи дают некоторые состояния запроса между debounce-событиями, но
  содержат только запросы к API; frontend может предварительно раскрыть
  синоним. Поэтому API `q` не всегда равен тексту поискового поля.

## События и ограничения сбора

| Внутреннее событие | Строк |
|---|---:|
| `search_query` | 2 669 |
| `search_select` | 669 |
| `search_abandon` | 284 |
| `compare_search` | 151 |
| `table_search` | 132 |

Источник истины — `frontend_events`. Выборка охватывает все имена с
`search`/`query`, а также любые события с параметром `q` или `query`;
отдельного обнаруженного хранилища search typing в PostgreSQL нет.
`compare_search` может дублировать спрос, уже записанный `search_query`;
суммарное число событий нельзя назвать числом запросов или попыток.

Baseline `useSearchTracking` записывает trimmed `q` после 900 мс,
обычно начиная с 2 символов, и обрезает его до 60 символов. До исправления
глобальный поиск писал до 120 символов. `DataTable` имеет отдельный debounce 250 мс и
`table_search{query,results}`; 85 из 132 его исторических строк не содержат
result count. До нового контракта невозможно восстановить быстрый набор,
удаление, вставку или изменение текста между сохранёнными состояниями.

`behavior.js` **не снимает текст input/textarea/contenteditable**; keydown
используется только для активности. Исторические события `search_select`/`search_abandon`
исторически не несут `context`, `interaction_id` и candidate set. Не записаны
состояние загрузки, полный набор кандидатов, точный scope и успешность
ответа на намерение после перехода. Техническая сессия sessionStorage,
серверная 30-минутная сессия и человек — разные сущности.

Наблюдавшиеся effective settings production: `frontend_events_enabled=true`,
`analytics_enabled=true`, `clickhouse_enabled=true`,
`behavior_raw_retention_days=0`. Ноль отключает очистку behavior history.
`analytics_default_retention_days=180` и `analytics_raw_log_retention_days=90`
существуют в настройках, но поиск ссылок в backend обнаружил их только в
декларации; они не доказывают работающую очистку этого датасета. Наличие
current settings не доказывает отсутствие старых потерь/откатов.

Отдельная обнаруженная граница: `track()` фильтрует automation, но не
проверяет explicit consent opt-out, в отличие от `behavior.js`. Изменение
этого контракта в данном read-only аудите не выполнялось.

## Реальные пути: все 919 и подробная выборка 150

В 3 905 событиях обнаружены **919 технических клиентских сессий** и
597 непустых visitor hashes. Все 919 последовательностей проанализированы
детерминированным скриптом с сохранением запросов, выбора, результатов,
переходов и ограничений доказательства. Классификация:

- **719 human_supported:** есть клики без synthetic flag, активное внимание
  новой версии или движение вместе со скроллом; обнаруженных internal/bot
  признаков нет. Это поддерживает гипотезу использования человеком,
  но не устанавливает личность или гарантированную человечность.
- **19 internal:** stored server session помечена собственной активностью.
- **181 unknown:** положительного свидетельства для классификации недостаточно.
- **0 bot_signals** в поисковой подвыборке по доступным UA/webdriver,
  square-screen/server-CPU, synthetic-click и stored server-bot данным.
  Это не утверждение, что во всей истории нет скрытых ботов.

Из human_supported сессий выбраны **150 реальных путей**, чередуя
context/device/outcome. Файлы `journeys-150.json` и `journeys-150.csv` содержат
наблюдаемую последовательность и предпочтительное поведение для каждого;
все 919 — `all-client-journeys.ndjson.gz`. Свёрнутые последовательности всех
150 дополнительно просмотрены при аудите: **674 поисковых события и 553
сохранённых query states**; 87 desktop, 48 mobile, 2 tablet, 13 без portrait.
58 путей имеют нулевую выдачу, 56 — выбор, 27 — abandon, 21 — выбор ниже top-3.
Один путь может входить в несколько этих категорий.

## Метрики, пригодные для исходной точки

- 1 054 из 2 669 `search_query` имеют записанный results=0: **39,5%**.
  Явно размеченный global: 180 из 568, **31,7%**. Это событийная доля,
  потенциально включающая pending sample; не доля неуспешных людей.
- В 470 из 919 client sessions есть нулевой результат; в 446 есть выбор.
  В 509 сохранено больше одного query state. Эти множества пересекаются.
- У 513 из 669 выборов записан position; **208 из 513, 40,5%**, ниже top-3.
  У 156 выборов position отсутствует. Глубокий выбор показывает основание
  проверить ранжирование, но не причинную меру плохого поиска.
- 1 293 из 2 669 query events не имеют context. Нельзя автоматически
  присвоить все эти исторические строки глобальному поиску.
- Явно сохранённые query contexts: global 568, region-profile 525,
  regions-list 113, map-metric 65, compare-macro 51, compare-world-concept 11,
  compare-country 10, world-chart-countries 10, calc-country 9,
  compare-region 8, compare-region-indicator 4, world-regions-hub 2.
  Отсутствие событий других текущих hooks не доказывает отсутствие поля или
  пользователей. Нужна browser acceptance каждой поверхности.

`query-demand.csv` содержит спрос с раздельными human_supported/internal/
unknown счётчиками. `historical-search-clicks.ndjson.gz` содержит 669
наблюдаемых выборов; **377** имеют непустой q и human_supported сессию.
Это слабые метки действий, а не готовая обучающая выборка релевантности.

## Математические методы и ML: что эти данные позволяют

Сначала нужен полный единый индекс доступных сущностей: страны, субъекты,
показатели, категории, понятия, валюты, family/variant/frequency и тип
страницы. Полнота индекса проверяется против coverage matrix, независимо
от популярности: редко выбираемый ряд всё равно должен находиться.

Наблюдения поддерживают retrieval из нормализованных токенов,
билингвальных алиасов, морфологии, альтернативной раскладки и
контролируемого расстояния редактирования. Ранжирование должно учитывать
целую фразу, страну/регион, понятие и доступный вариант. BM25/TF-IDF,
token coverage и trigram similarity дают воспроизводимую исходную модель;
явное противоречие географии/понятия не исправляется повышением популярности.

669 выборов пока не дают надёжного learning-to-rank: часть без текста,
часть с отсутствующим position, candidate set/exposure/loading state не
сохранены, intent satisfaction не размечен. Непустые 377 выборов могут
дать weak-label Recall@k проверку найденного выбранного объекта, но
`cpi usa` → Russia и похожие случаи надо отдельно рецензировать. Без
candidate set нельзя честно объявить NDCG, unbiased click-through или
каузальный выигрыш. Перед обучением нужны ручные relevance judgments по
150 путям, held-out split без повторов одинакового intent и новая корректная
телеметрия поиска. Исторические запросы остаются локально; передача в
внешнюю модель для этого аудита не требовалась.

## Воспроизводимость и оставшееся неизвестное

Команды из корня проекта:

```bash
python3 scripts/search-history-audit.py
python3 scripts/search-history-analyze.py
```

Первая команда подключается к production только для чтения и создаёт новый
снимок PG плюс отдельные CH/nginx выгрузки; повтор заменяет файлы выбранного
output-каталога, поэтому для сохранения старого снимка следует задавать
отдельный `--output`. Вторая анализирует локальные gzip-файлы без сети.
`--print-sql` первой команды работает без production access. Отдельные
`--clickhouse-only`/`--nginx-only` дополняют существующий manifest.

Проверено: successful read-only transaction, gzip reread count/SHA256,
игнорирование raw-каталога Git, анализ всех 919 клиентских последовательностей,
150 подробных путей и просмотр их свёрнутого ввода/выбора, CH reconciliation,
все удержанные nginx rotations, Python syntax. Локальный localhost:5434
прочитан без изменения runtime: Alembic `20260927_world_nonzero_idx`,
355 036 world indicators, 16 184 475 world points, 991 федеральный indicator,
96 регионов России, 495 regional indicators, 51 subnational region и
1 883 subnational indicators. Это наличие локальной БД, не приёмка нового API.

Не установлены: все введённые символы за прошлое; существование истории до
начала удержанных слоёв; relevance каждого выбора; causal failure rate;
точная причина CH time shift; visitor-to-person identity; сценарии полей,
для которых не сохранились события. Эти пробелы не заполняются синтетическими
«клиентами». Код выгрузки и отчёт локальные, без commit/push/deploy.

Основания: ADR-0007/0009/0010, `frontend/src/lib/{track,behavior,useSearchTracking}.js`,
`IndicatorSearch.jsx`, `DataTable.jsx`, `backend/app/api/analytics.py`,
`backend/app/{config,models}.py`, `analytics_scheduler.py`, `clickhouse_sync.py`,
`bot_score.py`, рецензии этих файлов, фактический schema/manifest и retained logs.
