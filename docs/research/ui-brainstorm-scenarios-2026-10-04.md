## Что реально происходит при первой загрузке (факты)

1. HTML 44 КБ с SSR-текстом `<main class="seo-page">`: eyebrow, H1, абзацы, три списка ссылок. Шапки, поиска, переключателя языка в SSR главной нет [curl: `seo-topbar` на главной = 0, на /russia/indicator/cpi = 5].
2. Полный CSS грузится через `media=print`+onload; `mountWhenCssReady` ждёт CSS до 2.5 с, потом `createRoot`, потом rAF и класс `fe-js` прячет SSR-тело [код: lib/mountWhenCssReady.js, spaReveal.js]. Фон SSR `#F8F9FC`, фон приложения `#EEF0F4` — смена оттенка в момент подмены.
3. JS до интерактива: main ~192 КБ gz + vendor 17 + query 25 + sessionReplay 14 + animation (gsap) 27 ≈ 275 КБ gz [curl/dist].
4. Планета грузится сразу после первого кадра, даже если она ниже экрана: PlanetView 6 КБ gz, PlanetScene (three) 264 КБ gz, worldTopology 48 КБ gz, текстура Земли 263 КБ, материал 90 КБ ≈ 585–670 КБ; потом «в простое» ещё countries-50m 230 КБ gz; при фокусе на микрогосударстве countries-10m 920 КБ gz [dist, curl]. Это в 2–3 раза больше всего остального JS.
5. Последовательность «загрузки» планеты: скелетон (shimmer, 512/576 px) → PlanetView монтируется с пустой сценой и крутилкой «Загружаем Землю…» → canvas fade-in 420 мс → вступительный поворот 1.4 с [код: HomeWorkbench.jsx, PlanetView.jsx, PlanetScene.jsx, PlanetView.css]. Таймаута у загрузки текстуры нет: если файл завис, крутилка вечная, до карты-фолбэка дело не доходит.
6. Поиск (hero-кнопка «inline» и лупа в шапке) открывает модалку. Запрос: debounce 300 мс → GET /api/v1/search?limit=100. Пока ждём, список обнуляется, показывается строка «Ищем…» без спиннера [код: IndicatorSearch.jsx, lib/useGlobalSearch.js].
7. Стенд через туннель: базовая задержка любого запроса ≈ 2.4 с (robots.txt); /search 2.4–5.0 с; «инфляция» отдаёт 100 результатов, 55 КБ (без сжатия); «ввп китай» 2.9 КБ; нелепый запрос → `reason: no_coverage`, 0 результатов [curl].
8. В каталоге стран планеты 55 стран, включая US, CN, IN, RU [curl].

## 30 сценариев

Формат: Делает → Видит → Что плохо → Правка.

### Десктоп 1440

**1. Студент, ноутбук 1440, Chrome, Wi-Fi.** Открывает главную, жмёт на hero-поиск, вводит «ввп китай».
Видит: hero → скелетон планеты → планета с поворотом; модалка с результатами через ~0.3 с + RTT.
Плохо: пока печатает «ввп», затем «ввп к…» — при каждой новой паузе список стирается в одну строку «Ищем…», высота модалки схлопывается и разворачивается (прыжок). Нет спиннера.
Правка: `useGlobalSearch.js` — `placeholderData: keepPreviousData` (держать прошлую выдачу полупрозрачной); `IndicatorSearch.jsx` — резерв `min-h` у списка и тонкая полоска/спиннер в шапке модалки.

**2. Трейдер, Cmd+K сразу после загрузки.** Жмёт ⌘K, пока SSR-текст ещё на экране.
Видит: ничего (слушатель вешается только после монтирования React); потом работает.
Плохо: первые 1–3 с горячая клавиша молчит, а SSR-страница выглядит как обычный документ без поля поиска.
Правка: в SSR главной (`backend/app/services/seo_renderer.py`) добавить мини-шапку `seo-topbar` (CSS уже есть в критическом стиле) и простую GET-форму поиска; либо инлайн-слушатель, запоминающий «⌘K был нажат» и открывающий модалку после монтирования.

**3. Журналист ищет «инфляция», десктоп.** Вводит слово целиком.
Видит: 100 результатов (55 КБ), первые — ИПЦ, недельный рост, инфляция недельная/годовая/квартальная; внизу «уточните запрос» [curl, код].
Плохо: тяжёлый ответ ради ~8 видимых строк; разброс «недельная/квартальная» выше «годовой инфляции», которую ищут чаще.
Правка: для набора на лету `limit: 30` (полный список — по кнопке «Показать ещё»); ранжирование — на стороне backend (годовая выше недельной), вынести в бэклог.

**4. Любой с мышью, первый клик по планете.** Кликает по Германии на глобусе.
Видит: выбор страны, карточка справа, подпись «Нажмите, чтобы выбрать» → второй клик открывает страницу [код: `activateCountry`].
Плохо: человек ждёт перехода по первому клику; две ступени непонятны, пока не прочитан мелкий hover-текст 10 px. Колесо мыши не зумит (осознанно), но подсказки об этом нет.
Правка: PlanetView.jsx — в карточке сделать «Открыть» главной кнопкой уже видимой (так и есть) и добавить в `planet-select-hint` фразу «Нажмите ещё раз — откроем страницу»; hover-small 10→12 px.

**5. Пользователь на 1440 с масштабом 125–150% (пенсионер на ноутбуке).** Смотрит главную.
Видит: при 150% эффективная ширина ~960 CSS px, hero в одну колонку (lg ≥1024), планета 480 px, справа колонка 332 px.
Плохо: массив текста 9–11 px (`planet-attribution` 9 px, eyebrow 10 px, `planet-list-footer` 10 px, ранг 10 px, подписи статистики 11 px) — трудно читать.

### Телефоны

**6. Россиянин, iPhone Safari 390, 4G.** Тапает по hero-«полю» поиска.
Видит: модалка открывается, `inputRef.focus()` вызывается через `setTimeout(…, 30)` [код: IndicatorSearch.jsx ~l.172].
Плохо: [проверить] iOS Safari открывает клавиатуру только если focus() вызван синхронно из обработчика жеста; отложенный через таймер — клавиатура может не появиться, человек видит модалку без клавиатуры и тапает по инпуту второй раз. Плюс при открытой клавиатуре `max-h-[60vh]` у списка не учитывает клавиатуру: нижние строки под ней.
Правка: фокус в самом `onClick` (после `flushSync(setOpen(true))` или через `autoFocus` на портале); высоту панели считать по `visualViewport.height`; на ≤sm скрывать абзац `search.help` (занимает 3–4 строки до результатов).

**7. Россиянин, Android Chrome + Gboard, вводит «инфляция».** Печатает слово без пробела.

Gboard держит слово в composition-состоянии (compositionstart на первой букве, compositionend при коммите). Итог — бесконечное «Ищем…», хотя запроса нет. На iPhone/десктопе не проявляется.
Правка: `IndicatorSearch.jsx` — не блокировать запрос по `isComposing` для не-CJK (проверять `/[぀-ヿ㐀-鿿가-힯]/` в значении) либо слать запрос при composing с debounce; `isSearchPending` не включать `isComposing`. Правка: HomeWorkbench.jsx — скелетон повторяет структуру (тулбар + сцена `var(--planet-scene-height)` + строки списка) или фиксировать `min-height` обёртки; PlanetView.css — на ≤700 px показывать короткую подпись «Нажмите страну» под сценой.

**10. Телефон: выбор страны из списка под глобусом.** Тапает «Германия» в списке (внизу блока).
Видит: строка подсвечивается, камера улетает к стране, но карточка выбранной страны выводится ВЫШЕ глобуса (`order:1` у `.planet-country-card`, `.planet-info{display:contents}`) — вне экрана [код: PlanetView.css @media ≤700].

### Сеть и устройства

**13. Медленный 3G (≈50 КБ/с).** Открывает с телефона в метро.
Видит: SSR-текст (44 КБ) — «документ без шапки»; через 6–10 с CSS+JS (275 КБ gz) → приложение; скелетон; ещё ~12 с до Земли (≈590 КБ) [расчёт по dist].
Плохо: планета качается безусловно, даже ниже экрана и в метро; она в 2 раза тяжелее всего остального JS; ощущение «сайт висит» (крутилка без прогресса); тратится трафик пенсионера.
Правка: HomeWorkbench.jsx — грузить PlanetView по IntersectionObserver; при `navigator.connection.saveData` или `effectiveType ∈ {slow-2g,2g,3g}` сразу показывать лёгкую SVG-карту (`WorldMap`, 22 КБ) с кнопкой «Показать 3D-Землю»; PlanetScene.jsx — таймаут 10 с на `loadAsync` → фолбэк.

**14. Дешёвый телефон ≤4 ГБ RAM / Save-Data.** Открывает главную.
Видит: бюджет `planetRenderBudget`: dpr 1, сфера 64×48, без детального материала при saveData [код].
Плохо: основная текстура `earth_day_2048.webp` (263 КБ) и three (264 КБ gz) всё равно грузятся; WebGL на слабом GPU может тормозить скролл страницы (canvas на странице, `antialias: true`).
Правка: PlanetScene.jsx — для `deviceMemory ≤ 4` брать 1024-текстуру (в public/planet уже лежит `earth_bump_roughness_clouds_1024`; day_1024 сделать), `antialias: !constrained`.

**15. Старый Android WebView / Chrome < 87 (пенсионер).** Открывает сайт.
Видит: Vite target по умолчанию (es2020) → `<script type=module>` с синтаксисом, который старый движок не разберёт → SSR-страница остаётся навсегда [код/вывод]. Это хороший фолбэк, но без поиска и шапки (см. №2).
Плохо: человек видит «документ» и не понимает, как искать; ссылки на страны работают.
Правка: SSR главной — шапка + форма поиска (см. №2); `vite.config.js build.target` — осознанно решить (es2019 ради 2–3% старых устройств); в PlanetView.jsx `useId().replaceAll` и `matchMedia().addEventListener` без проверки — ронять страницу на Safari ≤13 (ErrorBoundary на всю главную) [проверить], заменить на `.replace(/:/g,'')` и `addListener`-фолбэк.

**16. Обрыв сети посреди загрузки чанка планеты.** Едет в лифте, главная уже показана.
Видит: `lazy(import('../PlanetView'))` отклонён → ошибка всплывает до App-`ErrorBoundary` (локальной границы вокруг планеты в HomeWorkbench нет) → вся главная заменяется экраном ошибки с «Перезагрузить»; `chunkRecovery` один раз перезагружает страницу автоматически (если не вводится текст) [код: App.jsx, ErrorBoundary.jsx, HomeWorkbench.jsx].
Плохо: из-за второстепенного блока пропадает hero и поиск.
Правка: HomeWorkbench.jsx — обернуть `<Suspense>` планеты в локальный `ErrorBoundary` с фолбэком «Карта не загрузилась · Повторить» (hero и поиск остаются); WorldMap-чанк внутри фолбэка PlanetView тоже под границу.

**17. Обрыв сети, пока ждёт ответ поиска.** Ввёл «инфляция Германии», Wi-Fi пропал.
Видит: «Ищем…» (без спиннера) до ошибки; ошибка «Не удалось загрузить результаты поиска» + «Повторить».
Плохо: считаю по коду: offline — axios `ERR_NETWORK` → 3 повтора интерцептора (0.5+1+2 с) × react-query `retry: 1` ≈ 8–9 с до ошибки; зависшее соединение — 15 с таймаут × 4 попытки × 2 ≈ до ~2 минут «Ищем…» без реакции [код: lib/api.js, useGlobalSearch.js]. Человек думает, что сайт сломан, и уходит.
Правка: useGlobalSearch.js — отдельный axios-конфиг для поиска: `timeout: 6000`, `__retryCount: RETRY_LIMIT` (без ретраев интерцептора), `retry: 0`; через 2.5 с ожидания в UI показывать «Сеть медленная… ещё ищем» и кнопку «Отменить/Повторить». Слушать `online`-событие и перезапрашивать.

**18. Ввёл запрос и сразу нажал Enter.** Быстро набрал «ввп» и Enter.
Видит: ничего. `handleListKey` ждёт `results[highlighted]`, а во время debounce/запроса `results = []` [код].
Плохо: Enter не даёт реакции — ни перехода, ни «ищем»; повторное нажатие тоже. Самый «ожидающий» момент поиска.
Правка: IndicatorSearch.jsx — по Enter при pending: пропустить debounce (`setSettled(needle)` сразу), помечать `pendingOpen=true`, и когда результаты придут — открыть первый (с подсказкой «Открыть первый результат?») или хотя бы подсветить поле/спиннер.

**19. Медленно печатающий пользователь (пенсионер), 3G.** Печатает «инфляц…» с паузами по 0.5 с.
Видит: на каждой паузе >300 мс уходит запрос по неполному слову и результаты мигают: прошлая выдача исчезает, «Ищем…», новая; каждый запрос по 1–5 с на плохой сети; отмена предыдущего через `signal` есть [код].
Плохо: мерцание и нагрузка на сервер; устаревший ответ не показывается (правильно), но человек не видит ничего.
Правка: `keepPreviousData`; минимум 2 символа для запроса (константа `SEARCH_MIN_LEN` есть только для аналитики); debounce 300→450 мс при `effectiveType` ≤3g; показывать «пока набирали: …» прошлую выдачу.

**20. Опечатка/запрос вне охвата («xyzqq», «курс биткоина на завтра»).** Ждёт ответа.
Видит: спустя секунды «Ничего не найдено по «xyzqq»» (backend отдаёт `reason: no_coverage` — в UI нет отдельной ветки и она падает в общий текст) [curl, код].
Плохо: тупик: нет подсказок, что искать; пример из `search.help` уже прокручен вверх.
Правка: `IndicatorSearch.jsx` — для `no_coverage` и «ничего не найдено» показывать 4–6 кликабельных примеров («Инфляция в России», «Ключевая ставка», «ВВП Китая») и ссылку «Все страны»; тексты в `i18n/messages.*.js`.

### Язык, регион

## Отдельно: ожидание ответа поиска

Как сейчас (код + замеры):
- Дебаунс 300 мс (`useGlobalSearch`) + запрос; состояние «ждём» = `isComposing || isDebouncing || isPending`.
- Пока ждём, `results = []` → в списке одна строка «Ищем…» (текст, `aria-live`, `aria-busy`), спиннера/скелетона нет; высота панели прыгает.
- Старая выдача не сохраняется (`keepPreviousData` нет) → мерцание при каждой паузе.
- Enter в этот момент ничего не делает.
- Пустой запрос: RU — полный список (≈100 показателей, сперва срез flagships из bootstrap, потом обновление → список «перескакивает»); EN — только США.
- Ошибка: после 3 ретраев интерцептора × `retry:1`; для «зависшей» сети до ~2 мин «Ищем…».
- Стенд (туннель): 2.4–5.0 с на запрос, при том что базовая задержка 2.4 с; на проде будет быстрее, но на 3G картина сохранится.
- Тяжёлый ответ: 100 строк/55 КБ на «инфляция» ради ~8 видимых.

Что сделать (по приоритету):
1. Состояние ожидания: тонкая индикаторная полоска (2 px, indeterminate) под полем + 3 строки-скелетона по высоте реальной строки (≈56 px) вместо одного текста; сохранить прошлые результаты, снизив opacity до .5.
2. Через 2.5 с ожидания — «Сеть медленная, ещё ищем…»; через 6 с — ошибка с «Повторить» (таймаут 6 с, без вложенных ретраев).
3. Enter = немедленный запрос без debounce + «открыть первый результат».
4. composition-ошибка Gboard (№7): не считать `isComposing` ожиданием.
5. `limit: 30`, при `has_more` — «Показать ещё»; кеш по префиксу: ответ на «инфл» фильтровать локально для «инфля».
6. Пустое состояние: «Популярное»/«Недавнее» (localStorage) вместо полного списка; для EN — смесь стран.
7. При `online`-событии автоматически перезапрашивать.

## Отдельно: анимация/ожидание загрузки главной

Как сейчас: SSR-текст («документ») → смена оттенка фона и подмена всего интерфейса → навбар GSAP fade (0.8 с + 0.2 с задержки; сначала рисуется видимым, затем уходит в opacity 0 — возможная вспышка [проверить]) → hero → скелетон-shimmer 512/576 px → пустая сцена + крутилка «Загружаем Землю…» → canvas fade 420 мс → поворот 1.4 с → подписи.

Проблемы:
- Три разных «ожидающих» вида подряд (shimmer → крутилка → fade) и нет ни одного с прогрессом; на 3G пустая сцена может висеть 10–15 с без объяснений и без таймаута.
- Высота скелетона не равна высоте готового блока (прыжок 100–220 px).
- Скелетон и `.pulse-dot` игнорируют `prefers-reduced-motion`.
- Смена фона `#F8F9FC` → `#EEF0F4` при подмене SSR.
- GSAP (27 КБ gz) в критическом пути ради fade навбара; CSS-анимации того же эффекта достаточно.

Правки:
1. Один непрерывный плейсхолдер планеты: статичный диск (SVG-круг или 8–10 КБ blur-постер из `earth_day`) нужной высоты → при готовности WebGL плавный cross-fade; текст-этапы «Загружаем карту → Рисуем страны».
2. Скелетон повторяет структуру PlanetView (тулбар + `var(--planet-scene-height)` + список) → нет прыжка.
3. Таймаут 10 с на текстуру/чанк и автоматический фолбэк в SVG-карту; под saveData/3g сразу SVG.
4. Навбар: заменить GSAP на CSS `@keyframes` (opacity/translate) с `animation-fill-mode: both` в начальном рендере (нет вспышки) — и убрать `animation` из предзагрузки.
5. Критический CSS: `body{background:#EEF0F4}` как у приложения.
6. Reduced motion: отключить shimmer/pulse; индикатор ожидания — статичный текст + пульс opacity.
7. Вступительный поворот 1.4 с оставить, но пропускать, если пользователь уже тронул страницу (скролл/тап по поиску) — не отнимать внимание.

## Нерешённое / что проверить на устройствах
- №6 (iOS клавиатура после `setTimeout`-фокуса) и №7 (Gboard composition) — гипотезы по коду, нужны реальный iPhone и Android.
- №15 (Safari ≤13: `replaceAll`, `matchMedia.addEventListener`) — по коду, на устройствах не проверено.
- Мерцание навбара (GSAP `fromTo` после первой отрисовки) — запись экрана на медленном CPU.
- Реальное время /search на проде (стенд через туннель даёт +2.4 с к любой задержке).
