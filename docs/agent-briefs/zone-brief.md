# Шаблон брифа: исполнитель зоны

Выдаётся каждому исполнителю зоны (worktree на зону). Подставь `<ЗОНА>`, `<СПИСОК-ФАЙЛОВ>`, `<ПУНКТЫ>`, `<КАТАЛОГ-ОТЧЁТОВ>`. Процесс — [agent-orchestration](../agent-orchestration.md).

---

## Прочитай перед работой (в этом порядке)

1. [docs/design-system.md](../design-system.md): раздел «Принципы владельца» (приоритет выше всего), затем слои стекла, запреты и исключения, бюджет блюра, правила движения.
2. [AGENTS.md](../../AGENTS.md) и [docs/knowledge-workflow.md](../knowledge-workflow.md): цикл знаний, который ты выполняешь сам в конце.
3. `<PLAN>`: твоя зона (файлы исключительные), общие запреты, твои пункты `<ПУНКТЫ>`.
4. Образ материала (если есть): `<КАДРЫ-ОБРАЗЦЫ>`.

## Как работать

- Worktree: `git reset --hard <ИНТЕГРАЦИОННАЯ-ВЕТКА>` (если нужных токенов базы нет, остановись и сообщи: база неверная).
- Сделай **каждый** пункт зоны или честно объясни, почему нельзя. Пункты A обязательны.
- Правь только файлы своей зоны. Чужой файл: только необязательный prop одной строкой с пометкой в отчёте. Глобальные токены и общие компоненты не трогай; новый общий класс клади в свой `styles/<зона>-*.css` и опиши в отчёте.
- Нельзя трогать `backend/`, сгенерированные зеркала (`pageMeta.generated.json`), `sitePaths.js`, `seo_*`, h1, title, мета и существующие тексты, если зона не бэкендовая. Новые тексты: ключи с префиксом зоны блоком `// ===== <Зона> =====` в конце `messages.ru.js` и `messages.en.js` (оба языка, иначе падает тест паритета); без жаргона.
- Форму задают свет и тень, не линии: никаких `border`, `outline` (кроме `:focus-visible`), Tailwind `border*`, `ring-*`, `box-shadow: 0 0 0 Npx` без размытия, золотых кромок. Разрешённые исключения — только список в design-system. Принципы владельца соблюдай и там, где старый код им противоречит (игровые глянцевые элементы, жёлтая заливка, диапазон в прогнозе).
- Анимировать только `transform`, `opacity`, `background-position`; всё под `prefers-reduced-motion` и `data-fe-motion`/`data-fe-lite`.
- Бюджет: не больше 12 слоёв `backdrop-filter` в кадре на компьютере и 6 на телефоне; длинные списки без blur; `backdrop-filter` делает предка контейнером для `position: fixed` (проверь `grep fixed` и порталы).
- Картинки: только в разрешении не ниже 2x от размера показа; webp; без текста на картинке; `width`/`height` заданы; ленивая загрузка кроме героя. Новые кадры генерируются скриптом `scripts/dev/generate-brand-image.py` (ключ в `api_key.txt`, никогда не печатать), промпт сохраняется рядом с кадром.
- Запускать можно: `cd frontend && npx vitest run <свои файлы или src>`, `npx eslint src`, `npm run build`. Серверы, Docker, браузер и симуляторы не запускать: вид проверяет оркестратор.
- Тесты: существующие не ломать (менять осознанно с объяснением), на новые компоненты короткие тесты; `styles/no-borders.test.js` остаётся зелёным.
- В конце выполни цикл знаний для своих файлов (строки реестра, документ темы) либо передай список оркестратору.
- Коммиты в своём worktree по смыслу: `feat(ui): <зона> — <суть>`.

## Отчёт `<КАТАЛОГ-ОТЧЁТОВ>/impl-<ЗОНА>.md`

1. Коммиты (хеш, что внутри).
2. Таблица `ID | статус (сделано / частично / не сделано) | файлы | что изменилось для глаза (размер экрана, страница) | если не сделано, почему`.
3. Правки вне списка зоны (файл, строка, зачем).
4. Исключения рамок, которые оставлены (селектор → пункт исключений).
5. Blur-слои на твоих страницах: сколько в кадре на компьютере и на телефоне (расчёт по разметке) и где blur не поставлен из-за fixed-потомков.
6. Ассеты: имя, размер px и КБ, где подключён, ленивая ли загрузка, откуда взят.
7. Что не проверено без браузера и на что смотреть первым.

В ответе 8–12 строк итога.
