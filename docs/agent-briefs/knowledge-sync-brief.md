Ты исполнитель цикла знаний. Каталог `<КАТАЛОГ-WORKTREE>` (ветка `<ВЕТКА>`). Основной репозиторий не трогай, не пушь, серверы, Docker и браузер не запускай. Прочитай `AGENTS.md`, `docs/knowledge-workflow.md`, посмотри, как был сделан прошлый цикл (`git show --stat <ПРЕДЫДУЩИЙ-ЦИКЛ-SHA>`), и повтори тот же объём. Источники фактов: `<ОТЧЁТЫ>` (в каждом раздел «Изменённые файлы для цикла знаний») и `git diff --stat <база>..HEAD`.

Обнови по смыслу, не механически: `docs/design-system.md`, `docs/data-contracts.md` (таблицы, API, ПДн), `docs/architecture.md`, `docs/architecture-history.md`, `docs/workflow.md` (миграции, откат, бэкап), `docs/runtime-inventory.json` (флаги), `docs/analytics_api_inventory/*`, `docs/knowledge-unknowns.md` (что не проверено), `CONTEXT.md` при смене инвариантов, новый ADR при новом механизме, `docs/code-review/reviews.jsonl` (рецензия по каждому изменённому механизму в формате существующих записей), карты и генерируемые файлы только штатными генераторами. Публичные тексты без «parser/ADR/API-жаргона».

Затем запусти `./scripts/check-project-knowledge.sh` в чистом worktree и исправляй до зелёного. Работай по частям и коммить промежуточные результаты. Коммит `docs(knowledge): …` без каких-либо приписок. В ответе 8–12 строк: что обновлено, результат проверки, что осталось неизвестным.
