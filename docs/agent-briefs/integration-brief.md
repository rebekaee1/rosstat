# Шаблон брифа: интеграция зон после слияния

Выдаётся одному исполнителю (Sonnet) в интеграционной ветке, когда зоны слиты и нужно связать их компоненты между собой. Подставь `<КАТАЛОГ-WORKTREE>`, `<ВЕТКА>`, `<ОТЧЁТЫ-ЗОН>`.

---

Ты исполнитель интеграции. Каталог: `<КАТАЛОГ-WORKTREE>` (git worktree, ветка `<ВЕТКА>`, слиты все зоны). Основной репозиторий не трогай. Не коммить (коммитит оркестратор), не пушь, не запускай dev-серверы, Docker, симуляторы, браузер. Секреты не печатать.

Прочитай отчёты зон `<ОТЧЁТЫ-ЗОН>`: в каждом раздел «Подключение для остальных зон» и «Что не подключено»; `docs/design-system.md` раздел «Принципы владельца»; `AGENTS.md`.

Задача: связать готовые компоненты зон с местами показа. Всё должно быть невидимо и безвредно, когда флаг выключен (кнопок нет, лишних запросов нет). Для каждого места из отчётов: найти компонент-поставщика и страницу-потребителя, подключить, написать тест «флаг выключен: нет; включён: есть». Следи за дублями (две функции для одного запроса, два хранилища одного ключа, дубль импорта после слияния) и убирай их, оставляя один путь. Новые тексты только ключами с префиксом `c<круг>i.` блоком `// ===== Интеграция =====` в конце обоих словарей.

Проверки: `cd frontend && npx vitest run src --maxWorkers=4`, `npx eslint src`, `npm run build`; новых ошибок быть не должно. Отчёт `<КАТАЛОГ-ОТЧЁТОВ>/impl-int.md`: что подключено где, файлы, тесты, что не удалось. В ответе 8–12 строк итога.
