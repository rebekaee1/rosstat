# ADR-0008 — Региональный блок как bounded context (артефакт вместо ETL)

- **Status:** Accepted
- **Date:** 2026-07-02
- **Last verified:** 2026-07-02 (реализовано локально: 489 показателей × 96 территорий × 1990–2024, 960 926 точек, SSR/SEO/OG, дособор из архивных редакций).
- **Part of:** [`AGENTS.md`](../../AGENTS.md), [`CONTEXT.md`](../../CONTEXT.md), [`ADR-0003`](0003-seo-single-source-server-rendered.md).
- **Контекст:** задача владельца 2026-07-01 — региональный блок «максимально уверенно и качественно»: все регионы, drill-down регион → показатель, mobile-first (60% мобильного трафика), SEO с ~1400 до ~3600+ страниц.

---

## Контекст

Источник — сборник Росстата «Регионы России. Социально-экономические показатели»:
**годовое** издание, один Excel-архив приложений в год (20 разделов, ~460 листов).
До 2024 приложения выходили только в Word (.doc/.docx). Ряды годовые, глубина
2000+ (частично 1990+), пересматриваются целиком при каждом издании.

Это радикально отличается от макроблока: там 100+ живых источников с
месячной/недельной частотой, ETL по расписанию, derived-движок и прогнозы.
Тащить региональные ряды в ту же модель `Indicator`/`DataPoint` значило бы
засорить каталог (~500 псевдо-индикаторов × 96 территорий), сломать листинги,
прогнозную политику и идемпотентные инварианты ETL ради данных, которые
обновляются раз в год одним файлом.

## Решение

Региональный блок — **отдельный bounded context** с собственной осью
`регион × показатель × год`:

1. **Своя схема БД**: `regions` (96 территорий: РФ, 8 ФО, 85 субъектов,
   2 агрегата-остатка), `region_indicators` (489 показателей, 22 раздела),
   `region_data` (960 926 точек). Alembic-ревизия `20260702_add_regional_tables`.
   Никакого пересечения с `indicators`/`data_points`.
2. **Артефакт вместо ETL**: host-скрипты `scripts/regional/` парсят архивы
   Росстата в статический артефакт `backend/app/data/regional/`
   (`regions.json` + `indicators.json` + `data.csv.gz` + `parse_report.json`).
   Артефакт коммитится в репозиторий — данные переживают исчезновение
   источника by construction. `seed_regional.py` (entrypoint, после
   `seed_data.py`) идемпотентно заливает артефакт: метаданные upsert по
   slug/code, точки — skip при совпадении счётчика, иначе TRUNCATE + reload.
   Ежегодное обновление = прогнать парсер по новому архиву, закоммитить
   артефакт, задеплоить.
3. **Пайплайн артефакта — три стадии, порядок фиксирован**:
   - `parse_pril_2025.py` — базовый парсер актуального Excel-приложения;
   - `backfill_pril_2022_2023.py` — показатели, исключённые из издания 2025
     (внешняя торговля ФТС, госслужащие, ПИИ, лён, ж/д грузы, прожиточный
     минимум пенсионера, интернет/ПК в организациях) — из Excel-приложений
     2023/2022, раздел 21 «Внешняя торговля» добавлен;
   - `backfill_word.py` — Word-редакции через LibreOffice headless
     (.doc → .docx → python-docx): раздел 22 «Правонарушения» (изд. 2018 +
     2019) и продление 24 рядов в 1990-е из TOM2 (изд. 2003). Каждый
     extend-джоб проходит **кросс-сверку** на overlap-годах с текущим
     артефактом (медиана относительного расхождения ≤ 5%, иначе REJECT —
     так отсеялись пенсии до деноминации и растительное масло с другой базой).
4. **Реестр территорий** (`regions_registry.py`) — канонический словарь
   slug/имя/округ + нормализация имён строк Росстата (сноски, гомоглифы,
   переименования: Пермская область → Пермский край, Читинская → Забайкальский
   край) + масштаб строк РФ с укрупнённой единицей («Российская Федерация,
   тыс.» / «млрд руб.»).
5. **API** — 4 эндпоинта `/api/v1/regions*` (landing, catalog, профиль
   региона, показатель с рядом, рядом РФ, рангом и соседями), Redis-кэш.
   UI — 3 страницы (`RegionsHome`, `RegionProfile`, `RegionIndicatorPage`),
   переиспользуют дизайн-систему макроблока, но навигация построена вокруг
   drill-down региона (mobile-first, поиск, аккордеоны разделов).
6. **SEO** — по ADR-0003: SSR `/seo/regions|region/*` (`seo_regional.py`) с
   авто-генерируемым аналитическим текстом (динамика, ранги, сравнение с РФ,
   русская типографика), sitemap (+~41 тыс. URL), OG-картинки
   `/og/region/{slug}/{code}.png`, nginx-прокси.

## Что осознанно НЕ делаем

- **Прогнозы** на региональные ряды: годовая частота, пересмотры целиком —
  профанация (консистентно с политикой «не ставить прогноз куда попало»).
- **Derived-движок**: динамика Г/г считается на лету в API/SSR из ряда.
- **Смешивание с макро-каталогом**: региональные показатели не появляются
  в `IndicatorSearch`/категориях макроблока.
- **Новые территории 2022** (ДНР/ЛНР/Запорожская/Херсонская): в сборнике
  2025 их нет в большинстве таблиц; добавим, когда Росстат даст полные ряды.

## Инварианты

- Артефакт — единственный источник региональных данных; БД воспроизводима
  из него полностью (пользовательских данных в таблицах контекста нет).
- Пайплайн идемпотентен: повторный прогон любой стадии даёт байт-в-байт
  тот же счётчик точек.
- Каждый дособранный показатель несёт `note` о происхождении (публичным
  языком) и `source_note` с меткой редакции (для разработчика).
- Денежные ряды не продлеваются глубже 1998 (деноминация).
