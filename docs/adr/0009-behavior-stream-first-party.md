# ADR-0009 — Поведенческий поток first-party (behavior stream)

**Status:** Accepted
**Date:** 2026-07-03
**Context:** звонок владельца 2026-07-03 («видеокамера на сайт»: собирать всё
поведение до мелочей — под будущий data science и итеративные правки продукта
по данным; масштабная планка — 100k посетителей/день).

## Решение

Два слоя телеметрии с разными контрактами, НЕ смешивать:

| Слой | Что | Куда | Зачем |
|------|-----|------|-------|
| Бизнес-события | `track.js` — ~90 именованных целей, ручная разметка | `frontend_events` + цели Метрики | Воронки, CTA, дайджест |
| Поведенческий поток | `behavior.js` — автосбор БЕЗ разметки | `behavior_events` (отдельная таблица) | Сырьё для DS, UX-сигналы |

`behavior.js` собирает: `pageview` (каждый SPA-переход), `click` (каждый клик:
иерархический путь элемента страница→блок→элемент, текст, координаты, признаки
`dead`/`rage`), `move` (сэмплированная полилиния мыши), `dwell` (время на
странице + max скролл + счётчики при уходе), `copy` (что копируют).

Транспорт: буфер → `sendBeacon` батчами (10 с / 60 событий / pagehide) на
`POST /api/v1/analytics/behavior` → bulk-insert. Горячие поля кликов — в
колонках (`element_path`, `x/y`, `is_dead`, `is_rage`), остальное — `params_json`.

## Инварианты

1. **Отдельная таблица.** Объёмы на порядки больше `frontend_events`; сырой
   поток никогда не пишется в таблицу бизнес-событий.
2. **Retention сырья + вечные агрегаты.** Сырые строки живут
   `behavior_raw_retention_days` (90), чистка в 04:30 МСК
   (`behavior_retention_job`). Дневные агрегаты в Пульс-снапшотах
   (`snap["behavior"]`) — долгосрочная память после чистки.
3. **Приватность (152-ФЗ).** Keystroke-логирования нет; текст не снимается с
   `input/textarea/[contenteditable]`; явный отказ от аналитики в актуальной
   редакции consent-политики отключает сбор; `/embed/*` не собирается.
4. **Телеметрия не ломает UX.** Все сборщики passive, все отправки
   fire-and-forget с проглатыванием ошибок.
5. **dead/rage-клики — продуктовые сигналы**, идут в Пульс и LLM-отчёт:
   dead = клик в некликабельное (ожидание ≠ реальность), rage = серия злых
   кликов (элемент не отвечает).

## Последствия

- Пульс-снапшот получил секцию `behavior` (by_type, топ страниц/кликов,
  dead/rage, dwell по страницам, копируемое) — ассистент видит поведение.
- Вебвизор 2 Метрики уже включён (`consent.js`: webvisor, clickmap) — записи
  сессий для глаз; наш поток — сырые данные для вычислений. Дополняют друг
  друга, не заменяют.
- При росте к 100k/день первый лимит — размер таблицы: партиционирование по
  месяцам и/или ClickHouse — отдельным решением, когда поток станет >1M
  строк/день (сейчас преждевременно).
