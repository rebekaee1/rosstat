## Различия, которые нельзя потерять

- v2 сам расходится в двух местах: 0.3 выбирает специализированные CBR parsers, фаза2 повторяет единый `CbrApiParser`; начало запрещает `SEO_MAP`, фаза3 снова его упоминает. Это сохранённое расхождение проекта решения, а не новое требование.
- Возрастная структура из трёх групп не закрывает возрастно-половую пирамиду `age_group × gender`. Наличие `/demographics` не считается её выполнением.
- Отдельный scheduler на том же 4 vCPU host не закрывает обещание разнести frontend/backend по разным серверам. В нынешнем resource budget все сервисы конкурируют.
- IndexNow history replay шире первоначальной политики «cold только новые/изменённые». Текущий общий cap 30000/day и pause после прохода описывают исполнение; они не доказывают факт изменения каждого отправляемого URL.
- Старые `/en` маршруты, ручной sitemap пяти страниц, client SheetJS и frontend-only deploy заменены. Исходные причины (двуязычность, официальные данные, usable chart/export, discoverability) остаются в истории.

## Границы и действия для интегратора

Содержательный material gap этих трёх доступных планов закрыт: прочитаны все 1042 строки / 76434 байта, зафиксированы 40 решений с lineage и ограничениями. Дополнение не объявляет платформу целиком исправной и не закрывает каждое старое обещание автоматически.

Root может связать оба файла с materials/acceptance/history и ledger по своему протоколу. Shared docs/ledger этим читателем не изменялись. Непроверенные cabinet/API-product/SDK/RID/коммерческие результаты нужно сохранить в общем реестре неизвестных с границей доступа или отдельным критерием принятия; выполнение старого плана для этого не требуется.

Новые exhaustive searches, тестовые наборы, browser/SSH/production операции не запускались; сверка current anchors была адресной и использовала уже прочитанные датированные backend/client/ops досье. JSON содержит SHA каждого anchor на момент сопоставления; hash/presence не обозначают полное повторное чтение его тела или execution acceptance.
