# Сценарная проверка входа нового агента — 2026-09-30

## Условия и результат

Независимый агент получил только репозиторий, текущий `AGENTS.md` и обычную задачу: «Хочу сравнивать экономики стран в одном денежном представлении, а позже добавить новости и форум; сформулируй технические действия с сохранением нынешних возможностей». Память и история прошлых чатов не использовались. Сначала задача была только на чтение; затем ведущий агент разрешил исправить три обнаруженных расхождения в двух документах. Код, настройки, runtime, сервер и приложение не менялись; приложение, ETL, миграции и restore не запускались, коммит не создавался.

Fresh AGENTS-only проба состоялась в отдельном агенте: исходные ответы, найденные места и результаты основной исследовательской задачи ему не передавались. Первым проектным документом прочитан актуальный AGENTS с диска; дальнейшие маршруты выбраны по нему. Граница пробы — статическое понимание данного обычного промпта, поиск требований/истории/исходников, два дополнительных механизма и последующее сопровождение знаний. Исполнение приложения, визуальная приёмка, полный инвентарь сценариев и все K01–K12 в эту пробу не входят.

Начальный checkout: `main`, HEAD `05302ff1c4dbe104850116e6206d168ec4fa91d3`. `git status --short` показывал только чужие untracked `.artifacts/` и `assets/`; они сохранены и не включены в изменения. Эти факты получены локальными Git-командами в данном проходе. Последующие параллельные правки других агентов не становятся доказательствами данного отчёта.

Вход позволяет найти текущее устройство, причины старых решений и план влияния данной задачи. Чтение выявило три смысловых расхождения, хотя начальный knowledge guard был зелёным. Они исправлены точечно; повторная проверка ограничена изменёнными строками и названными зависимостями. **Это сценарная приёмка навигации и понимания, а не приёмка всего досье по K01–K12**, всей платформы или нового продукта. Полные условия K01–K12 значительно шире: `docs/code-review/readiness-criteria.md:88–99`.

## Два самостоятельно выбранных механизма полного инвентаря

Выбор сделан из общего инвентаря, а не ограничен валютными файлами: `docs/project-terrain.json:709` — Calendar API, `:712` — Embed API; слои API/services/jobs/embed перечислены в `docs/project-terrain.md:31–43`.

### Официальный календарь публикаций

Путь: UI `/russia/calendar` (`frontend/src/App.jsx:301–302`) → hooks (`frontend/src/lib/hooks.js:109,137`) → `/api/v1/calendar` (`backend/app/api/router.py:24`, `backend/app/api/calendar.py:17,88–148`) → `EconomicEvent` с stable/natural keys и provenance (`backend/app/models.py:573–613`). UI имеет loading/error/refetch (`frontend/src/pages/CalendarPage.jsx:153–154,219`); API list задаёт МСК-диапазон, pagination, locale key и TTL 900s (`backend/app/api/calendar.py:19,99–108,145–147`).

Producer: scheduler daily 03:00 MSK (`backend/app/main.py:487–495,570–577`) → `seed_calendar` (`backend/app/services/calendar_seed.py:493–506`) → official candidates из CBR/Росстат, blocking fetch в threadpool (`backend/app/services/calendar_sources/official_calendar.py:365–404`) → stable upsert и reschedule audit (`backend/app/services/calendar_sources/common.py:83–90,94–109,199`) → prune/enrichment. Это несколько write-фаз, не одна атомарная транзакция; рецензия фиксирует эту границу (`docs/code-review/reviews.jsonl:205`). После source failure explicit date не должна заменяться lower-confidence estimate.

Public guard требует `official_explicit` либо CBR `official_rule`, non-estimated и заполненные event_key/source_url/source_hash/last_seen_at. Просроченная scheduled date без actual_value даёт awaiting_confirmation, не released (`backend/app/api/calendar.py:23–56`). Причина исторического решения — ошибочная синтетическая дата CPI; старые Rosstat/Minfin rules после сверки 10.09 стали private estimates (`docs/adr/0005-official-calendar-source-bound.md:12–24,53–72`). Наличие legacy estimated builders в seed не делает их текущим public producer.

Ограничения проверки: исходники/рецензия прочитаны; API/browser/job не исполнялись. У official_calendar есть пределы curated дат, parsing timezone/ICS и stage atomicity (`docs/code-review/reviews.jsonl:205`). News scheduler или forum notification нельзя считать эквивалентом подтверждённой публикации economic event; этот механизм нужно сохранить самостоятельным.

### Embed: SVG/iframe и impression tracking

Два пути нельзя смешивать. Iframe `/embed/card/:code` (`frontend/src/App.jsx:228–232`) → `EmbedCard` → `useIndicator`/`useIndicatorData`, отдельные loading/error states и latest native data (`frontend/src/embed/EmbedCard.jsx:43–79`). SVG `/api/v1/embed/card/{code}.svg` → `Indicator/IndicatorData` с bounded history (`backend/app/api/embed.py:67–81,221–249`), CPI display adapter, versioned indicator/locale/theme/period key, cache TTL3600 (`:230–245,330`). Эти SVG сейчас читают российский Indicator, а не произвольный WorldIndicator. В валютном плане нельзя молча обещать world/converted support всех старых embed.

Impression: UI `sendBeacon` с code/type/referrer один раз на mount (`frontend/src/embed/useEmbedParams.js:39–51`) или GET pixel → Redis daily hash `fe:embed:imp:{date}` с domain, TTL90 дней (`backend/app/api/embed.py:435–485`). Ошибки tracking suppressed, ответ остаётся ok/pixel; warning каждые100 ошибок process-local (`:412–425,461–463`). Это count события показа; он не доказывает человека, уникального посетителя или запись в PostgreSQL. HINCRBY и EXPIRE — отдельные операции (`:459–460`); cache/state/session/analytics имеют разные persistence contracts.

Связанные границы: public API registration (`backend/app/api/router.py:25`), отдельный embed limiter (`backend/app/main.py:143–150`), attribution ссылки и старая совместимость. Card SVG ещё содержит legacy `/indicator/{code}` ссылку (`backend/app/api/embed.py:323–325`); удалять старые 301 нельзя. Рецензия описывает 400 invalid code, 404 card/badge missing, blank spark и fail-open tracking (`docs/code-review/reviews.jsonl:71`). Реальный iframe, CSP/CORS, новый world embed, browser cache и delivery impressions не проверены.

Quota, предел RAM, текущий расход и измеренная capacity различны. Новые FX/news/forum jobs должны оценивать cold/warm SSR/API + ETL/BI, p95/p99, SQL wait, throttling, disk latency, swap rates и storage retention; такой нагрузочной приёмки здесь нет (`docs/architecture.md:106,273`).

Новые tables/forum/media должны войти в full backup, restore acceptance и retention; старая identity-only копия не покрывает будущий пользовательский контент.

## Обязательный цикл после обычной задачи

Вход явно требует вести знания без специального запроса владельца: `docs/knowledge-workflow.md:3–18,24–36,39–61`. Изменение продукта затрагивает README/CONTEXT, architecture/contracts; источник/парсер — data_sources/docstring/seeds; mode/derived/forecast — recipes/playbook/generated; auth/analytics — ADR/inventory; ops — workflow/resilience/runtime observation. Новая architectural axis требует ADR с историей; план/неизвестное фиксируются в одном backlog, evidence — в code-review.

После реализации: сценарная проверка и UI browser → тематические документы → содержательная рецензия exactsource/delta → stage только своих файлов → symbols/coverage/terrain → material registry → knowledge/check-all и просмотр diff. Команды и distinction generator vs semantic reviewer даны в `docs/knowledge-workflow.md:41–77`. New subsystem расширяет K02–K09 и сквозные сценарии (`:81–94`). Source archive/history сохраняются, shadowed legacy не delete-list (`AGENTS.md:35–40`).

`check-project-knowledge.sh` не запускает app/сеть/сервер и проверяет AGENTS/reviews/terrain/materials (`scripts/check-project-knowledge.sh:1–28`). `check-all.sh` дополнительно запускает pytest/frontend tests/lint/build и может регенерировать repo-inventory (`scripts/check-all.sh:8–43`); полный check-all в данном cold-start проходе не запускался. После интеграции предложенных рецензий, staged отчёта и обновления карт/materials общий post-change pass остаётся отдельной обязанностью завершения общей задачи.

Состояние данного результата: **локальные docs corrections + отчёт + proposed reviews; без commit/push/deploy/live acceptance**. Неизвестное: реальная нагрузочная capacity, current images beyond selected hashes, full live schema, application restore/failover, и перечисленные новые продуктовые contracts. Подтверждённый результат ограничен этим входным сценарием и двумя самостоятельно выбранными механизмами.
