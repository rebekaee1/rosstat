# Backend: содержательная сверка изменений, 30 сентября 2026

**Основа:** локальная `main`, `972579f`. Это актуализация сохранённого разбора исходников, без изменения runtime, запуска джобов, обращения к серверу, коммита или деплоя. Ресурсы и фактически работающие настройки сервера проверяются отдельным operational-разбором.

## Метод и границы доказательства

В области backend guard нашёл **63 изменённых/новых пути**: API, справочники, ingestion, прогнозы, аналитика, SEO, задания, CLI/seed и тесты. Их список и прочитанные диапазоны приведены ниже. Для каждого прежнего файла найден Git blob, в точности совпадающий с SHA-256 сохранённой рецензии; все эти blobs совпадают также с версией файла в `f8e239a`. Затем прочитаны изменённые блоки и новые тела функций, проверены их вызывающие/использующие контракты. **83 именованных определения изменились, 153 добавлено**, включая классы и вложенные тестовые помощники.

Неизменённые определения сохраняют прежнее полное чтение и содержательные аннотации. Их нормализованный AST-body fingerprint проверен на равенство. Это основание переноса старой рецензии, а не заявление о повторном чтении каждого неизменённого тела. Изменение dependency или условий запуска может поменять результат даже при одинаковом AST; поэтому сквозные изменения описаны отдельно. `read_ranges` в предложенных rows обозначают покрытие *суммой прежнего разбора и этого delta-разбора*.

[Предложенные рецензии](backend-delta-reviews-2026-09-30.jsonl) содержат `review_basis`: старый commit/hash/read ranges, текущие прочитанные диапазоны, fingerprints неизменённых определений, сохранённую provenance и ручные аннотации новых определений. Общий ledger и машинные snapshots этим файлом не обновляются; их объединяет основной агент после сверки.

Тестовые исходники прочитаны; тесты в этом проходе не исполнялись. SQLite, fake Redis/CH/HTTP и static nginx assertions, даже при зелёном прежнем запуске, не подтверждают PostgreSQL transaction/race, реальный CH, nginx или выпущенный SHA.

### Границы новых механизмов

1. **Eurostat remap не является атомарной заменой dataset.** [Loader](../../backend/scripts/load-world-eurostat.py#L515) commit меняет slice до [записи фактов](../../backend/scripts/load-world-eurostat.py#L431). Если следующая запись завершится ошибкой, старые points могут временно остаться под новым slice; завершительный bump в `run` не будет достигнут. По исходникам это допустимый путь, наличие такого случая на production не измерялось. Existing same geo/hash принимается без numerical comparison; remap исчезнувшего slice опирается на matching history и уникальный лучший dimension score, не на формальное равенство методологий. Порог допускает до двух listed orphans даже в маленьком dataset; эти карточки сохраняют историю и не снимаются автоматически с листинга.
2. **Сессия через границу окна.** [sessionize](../../backend/app/tasks/analytics_rollups.py#L83) получает только текущие events; [run_rollups](../../backend/app/tasks/analytics_rollups.py#L683) вызывает непересекающиеся окна. Повторный pageview после границы начинает отдельный chunk, а первый dwell/click без pageview отбрасывается. [Новый тест](../../backend/tests/test_analytics2.py#L797) не содержит таких сессий. Это статическое следствие, пока не отдельный воспроизведённый defect.
3. **Bot filter не унифицирован.** [Python](../../backend/app/services/analytics_marts.py#L138), [SQL](../../backend/app/services/analytics_marts.py#L160), собственный [score](../../backend/app/services/bot_score.py#L41) и CH visits имеют разные populations. Hardware признаки могут отсечь необычного реального посетителя; это не доказательство, что весь оставшийся трафик человеческий. CH raw_metrika_visits sync не применяет not-headless фильтр.
4. **Bounded CH память не означает короткую DB phase для каждого слоя.** Append events закрывают PG перед insert; `_stream_partitions` держит analytics session между `yield`/CH insert. Identity links загружаются полностью. Executor устраняет loop blocking; предел RAM/DB hold-time требует отдельного измерения.
5. **Публикационная политика не менялась.** Решение владельца от 20 сентября включает все действующие canonical-страницы в sitemap. Demand/popularity фильтр и массовое 410 из внешних предложений не приняты. Eligibility sitemap и SSR ещё нужно сверить на today/общем периоде сравнений, как в прежних findings.

## Предлагаемые дополнения в верхние документы

- **CONTEXT:** старый абзац «derived запускается только при добавлении строк» не соответствует текущему `records_updated` dispatch; оставить историю ограничения ADR-0002, рядом уточнить действующий механизм. Currency canonical exceptions, annual horizon=1 и неравные populations аналитики должны быть явными доменными правилами. Истории инцидентов 29 сентября сохраняются с датой, их runtime claims требуют operational evidence.
- **Architecture:** Eurostat structure migration — отдельный state transition, но с несколькими commit boundaries; CH — disposable copy с append/replacing семантиками; knowledge guard использует prior+delta evidence, не считает hashes пониманием.
- **README:** путь onboarding должен приводить к current dossier/contracts/findings и разделять local Vite/API/Compose и production. Статус актуальности указывать по commit и датированной ops-проверке.

Полный platform audit здесь не закрывается: auth и неизменённые API опираются на прежнее чтение; production data, restore, concurrent PostgreSQL/Redis, серверная пропускная способность, реальные SSR/CSR payloads, accessibility/mobile и внешняя индексация требуют отдельных свидетельств.
