# Forecast Economy — инструкции агенту

Актуализировано 2026-09-30. Общение с владельцем — по-русски, коротко и по факту.
Владелец описывает результат обычным языком. Чтение проекта, проверка связей,
реализация и сопровождение знаний входят в работу агента для каждой задачи.

## Начало задачи

1. Проверь ветку, HEAD и рабочие изменения. Различай локальную `main`, чужие
   незакоммиченные правки, локальный контейнер и реально выпущенный SHA.
2. Прочти [обзор](README.md), начало [CONTEXT](CONTEXT.md) и относящиеся к задаче
   инварианты. Найди подсистему через [архитектуру](docs/architecture.md),
   [контракты](docs/data-contracts.md) и [рельеф](docs/project-terrain.md).
3. Перед изменением прочти текущую реализацию, её рецензию
   (`docs/code-review/reviews.jsonl`), относящиеся ADR и старые основания по
   [истории](docs/architecture-history.md). Следуй связям до producer/consumer,
   UI/API/jobs, хранилища, кэша и настроек, которые затрагивает задача.
4. Сверь требование, реализованное поведение и проверенное поведение окружения.
   Неизвестное запиши с источниками поиска и следующим способом проверки.

## Условия работы

- Сохраняй полезную историю. У старого решения уточняй дату, статус и заменивший
  механизм; первоначальные причины сохраняй в ADR/архиве. Перед удалением выясни
  consumers и редиректы. `shadowed_legacy` и граф связей не являются delete-list.
- Главные механизмы российских индикаторов: `PARSER_REGISTRY`, `DERIVED_SPECS`,
  `forecast_strategies/registry.py`, generic `FamilyDef` → generated JSON →
  `viewModeEngine`. Bespoke CPI/PPI/housing и Россия как bounded context имеют
  отдельные действующие контракты.
- Все действующие публичные canonical входят в sitemap по решению 20 сентября;
  существование SSR и редиректы проверяются отдельно. Карточки стран используют
  country-first URL; валютный раздел — `/currencies/indicator/{code}`. Язык
  задаётся хостом. Исторические цифры не заменяют живой каталог.
- Источники экономических рядов — официальные; для зарубежных национальных
  рядов приоритет у доступного национального первоисточника. Методология и
  публичные тексты объясняют смысл без parser/ADR/API-жаргона.
- Сервер имеет 4 vCPU; web/scheduler, PostgreSQL, Redis, ClickHouse и host делят
  ресурсы. Число workers, CPU-квота и измеренная производительность — разные
  вещи. Точные значения и дата проверки находятся в runtime-досье.
- Сохраняй чужие правки. Законченную проверенную работу коммить отдельно;
  push и production deploy выполняй только по явной команде владельца.
  Релизные проверки и совместимость миграций — в workflow.

## Завершение задачи

Задача завершена после реализации, проверки сценария и актуализации всех
затронутых источников знаний по [knowledge-workflow](docs/knowledge-workflow.md).
`./scripts/check-project-knowledge.sh` и `./scripts/check-all.sh` проверяют
согласованность. Генератор обновляет структуру; смысл и рецензии обновляет
прочитавший изменения агент. Зелёный hash-check не доказывает поведение.

В итоговом сообщении укажи результат, проверки, оставшееся неизвестное и
состояние: локально / commit / push / deploy / live acceptance.
